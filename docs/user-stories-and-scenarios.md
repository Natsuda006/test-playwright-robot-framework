## 1. บทนำ (Introduction)
เอกสารฉบับนี้จัดทำขึ้นเพื่อแยกและส่งมอบเฉพาะขอบเขตงานส่วนบุคคลของ **นางสาวณัฐสุดา ร่องทอง (664259006)** จากเอกสารโครงงานกลุ่ม สำหรับฟีเจอร์แผงควบคุมผู้ดูแลระบบ (Admin Dashboard - US-15) และระบบจัดการผู้ใช้งาน (Admin User Management - US-16) ของระบบ T-Check โดยใช้รูปแบบ **Gherkin (Given-When-Then)** ตามแนวทาง **Behavior-Driven Development (BDD)** เพื่อใช้เป็นกรณีทดสอบอัตโนมัติแบบ End-to-End (E2E)

### 1.1 โครงสร้างการเขียน BDD (Gherkin Syntax)
| คำสำคัญ | ความหมาย |
| :--- | :--- |
| **Given** | เงื่อนไขตั้งต้น / สถานะของระบบก่อนเริ่มทดสอบ (Precondition) |
| **When** | การกระทำของผู้ใช้ (Action / Event) |
| **Then** | ผลลัพธ์ที่คาดหวังจากระบบ (Expected Outcome) |
| **And** | เงื่อนไข การกระทำ หรือผลลัพธ์เพิ่มเติมที่สืบเนื่องจากบรรทัดก่อนหน้า |

### 1.2 ข้อมูลตั้งต้นสำหรับการทดสอบ (Test Fixtures & Environment)
- ผู้ทดสอบใช้บัญชีผู้ดูแลระบบ (Admin) ที่มีสิทธิ์เข้าถึงหน้าแดชบอร์ดและข้อมูลการใช้งานตามสภาพแวดล้อมทดสอบจริง
- `TARGET_USERNAME`: ชื่อผู้ใช้เป้าหมายในการทดสอบ (ค่าเริ่มต้น: `nan006`)
- `TARGET_ROLE`: สิทธิ์การใช้งานเป้าหมายในการทดสอบ (`user-pro` หรือ `user-free`)
- `AUTH_STATE`: ไฟล์จัดการ Session การเข้าสู่ระบบของ Admin (`playwright/.auth/admin.json`)

## 2. User Stories และ Test Scenarios

### US-15: ดูแดชบอร์ดผู้ดูแลระบบ (Admin Dashboard)

| หัวข้อ | รายละเอียด |
| :--- | :--- |
| **User Story** | ในฐานะ **ผู้ดูแลระบบ (Admin)**<br>ฉันต้องการ **ดูแดชบอร์ดผู้ดูแลระบบ**<br>เพื่อ **ติดตามภาพรวมการใช้งานและตรวจสอบสถานะของระบบได้อย่างรวดเร็ว** |
| **ผู้เกี่ยวข้อง (Actor)** | ผู้ดูแลระบบ (Admin) |
| **อ้างอิง Use Case** | UC-15: ดูแดชบอร์ดผู้ดูแลระบบ |

#### Scenario 15.1: เปิดแดชบอร์ดและแสดงข้อมูลสรุปภาพรวม (TC-ADM-001)
- **Given** ผู้ดูแลระบบเข้าสู่ระบบสำเร็จและมีสิทธิ์เป็น Admin
- **When** ผู้ดูแลระบบเปิดหน้า “แดชบอร์ดผู้ดูแล” (`/admin`)
- **Then** ระบบแสดงหน้า “แผงควบคุมผู้ดูแลระบบ”
- **And** ระบบแสดงจำนวน “ผู้ใช้งานทั้งหมด”
- **And** ระบบแสดงจำนวน “ผู้ใช้งานระดับ Pro”
- **And** ระบบแสดงจำนวน “ผู้ใช้ธรรมดา”
- **And** ระบบแสดงจำนวน “ผู้ใช้งานที่ถูกระงับ”
- **And** ระบบแสดง “การเรียกใช้ AI (วันนี้)”
- **And** ระบบแสดง “โทเค็นที่ใช้ไปวันนี้”
- **And** ระบบแสดง “อัตราข้อผิดพลาด (Error Rate)”
- **And** ระบบแสดง “เวลาตอบสนองเฉลี่ย”

#### Scenario 15.2: แสดงกราฟและข้อมูลสถิติย้อนหลัง 7 วัน (TC-ADM-002)
- **Given** ผู้ดูแลระบบอยู่ที่หน้าแดชบอร์ดและระบบมีข้อมูลการใช้งาน
- **When** ผู้ดูแลระบบตรวจสอบข้อมูลสถิติต่างๆ บนแดชบอร์ด
- **Then** ระบบแสดงหัวข้อ “ปริมาณการใช้โทเค็น (7 วันย้อนหลัง)” พร้อมคำอธิบาย “จำนวนโทเค็นที่ถูกใช้งานในแต่ละวัน”
- **And** ระบบแสดงหัวข้อ “จำนวนการตรวจสอบคำผิด (7 วันย้อนหลัง)” พร้อมคำอธิบาย “จำนวนครั้งที่เรียกใช้งาน AI ในแต่ละวัน”
- **And** ระบบแสดงส่วนกราฟสถิติ (Application element) จำนวน 2 กราฟ และแสดงผลอย่างถูกต้อง

#### Scenario 15.3: แสดงข้อมูลผู้ใช้งานล่าสุดบน Dashboard (TC-ADM-003)
- **Given** ผู้ดูแลระบบอยู่ที่หน้าแดชบอร์ด
- **When** ผู้ดูแลระบบตรวจสอบส่วน “รายชื่อผู้ใช้งานล่าสุด”
- **Then** ระบบแสดงหัวข้อ “รายชื่อผู้ใช้งานล่าสุด” พร้อมคำอธิบาย “ผู้ใช้งานที่เพิ่งสมัครหรือมีความเคลื่อนไหวล่าสุด”
- **And** ระบบแสดงตารางข้อมูลผู้ใช้งาน
- **And** ตารางแสดงคอลัมน์ “ชื่อผู้ใช้”, “ระดับสมาชิก”, “โทเค็นที่ใช้ไปวันนี้”, และ “วันที่ใช้งานล่าสุด”

#### Scenario 15.4: ตรวจสอบการแสดง Dashboard เมื่อโหลดข้อมูลสำเร็จ (TC-ADM-004)
- **Given** ผู้ดูแลระบบเข้าสู่ระบบสำเร็จและระบบสามารถโหลดข้อมูล Dashboard ได้ตามปกติ
- **When** ผู้ดูแลระบบเปิดหน้า “แดชบอร์ดผู้ดูแล”
- **Then** ระบบแสดงหน้า “แผงควบคุมผู้ดูแลระบบ” และข้อมูลผู้ใช้งานทั้งหมด
- **And** ระบบไม่แสดงข้อความ “ไม่สามารถโหลดข้อมูลได้ กรุณาลองใหม่”

#### Scenario 15.5: กรณีระบบไม่สามารถโหลดข้อมูล Dashboard ได้ [Negative] (TC-ADM-005)
- **Given** ผู้ดูแลระบบเข้าสู่ระบบสำเร็จและมีสิทธิ์เป็น Admin
- **And** เกิดสภาวะการเชื่อมต่อดึงข้อมูลขัดข้อง (Simulated 500 API Response)
- **When** ผู้ดูแลระบบเปิดหน้า “แดชบอร์ดผู้ดูแล”
- **Then** ระบบยังคงแสดงหน้าโครงสร้าง “แผงควบคุมผู้ดูแลระบบ” และข้อมูลส่วนพื้นฐานได้
- **And** ระบบไม่แสดงข้อความแจ้งเตือน Error Dialog หรือ Pop-up Alert รบกวนผู้ใช้
- **And** ระบบไม่แสดงข้อความ “ไม่สามารถโหลดข้อมูลได้ กรุณาลองใหม่”

### US-16: จัดการผู้ใช้งาน (Admin User Management)

| หัวข้อ | รายละเอียด |
| :--- | :--- |
| **User Story** | ในฐานะ **ผู้ดูแลระบบ (Admin)**<br>ฉันต้องการ **ค้นหา กรอง เปลี่ยนระดับสมาชิก ระงับบัญชี และลบบัญชีผู้ใช้งาน**<br>เพื่อ **ควบคุมสิทธิ์การใช้งานและดูแลความเรียบร้อยของผู้ใช้ในระบบ** |
| **ผู้เกี่ยวข้อง (Actor)** | ผู้ดูแลระบบ (Admin) |
| **อ้างอิง Use Case** | UC-16: จัดการผู้ใช้งาน |

#### Scenario 16.1: ค้นหาผู้ใช้จากชื่อหรืออีเมล (TC-ADM-USR-001)
- **Given** ผู้ดูแลระบบอยู่ที่หน้ารายการผู้ใช้งาน (`/admin/users`)
- **When** ผู้ดูแลระบบระบุชื่อผู้ใช้เป้าหมาย (`TARGET_USER`) ในช่องค้นหา “ค้นหาจากชื่อ หรืออีเมล...”
- **Then** ตารางแสดงผลลัพธ์ผู้ใช้งานที่ค้นพบจำนวน 1 รายการ
- **And** ข้อมูลในแถบตารางประกอบด้วยชื่อผู้ใช้ตรงตาม `TARGET_USER`

#### Scenario 16.2: กรองรายชื่อผู้ใช้ตามสิทธิ์ระดับสมาชิก Pro (TC-ADM-USR-002)
- **Given** ผู้ดูแลระบบอยู่ที่หน้ารายการผู้ใช้งาน (`/admin/users`)
- **When** ผู้ดูแลระบบเลือกตัวกรองระดับสมาชิกเป็น “user-pro”
- **Then** ตารางแสดงรายการผู้ใช้งานที่มีระดับสมาชิกเป็น “user-pro” ทั้งหมด
- **And** ตารางไม่แสดงรายการผู้ใช้งานที่มีระดับสมาชิกเป็น “user-free”

#### Scenario 16.3: เปิดดูรายละเอียดผู้ใช้ (TC-ADM-USR-003)
- **Given** ผู้ดูแลระบบค้นหาผู้ใช้เป้าหมายสำเร็จในหน้ารายการผู้ใช้งาน
- **When** ผู้ดูแลระบบกดลิงก์ “ดูรายละเอียด” ของผู้ใช้เป้าหมาย
- **Then** ระบบเปลี่ยนเส้นทางไปยังหน้า URL รายละเอียดผู้ใช้ (`/admin/users/[userId]`)
- **And** ระบบแสดงหัวข้อชื่อผู้ใช้ (`TARGET_USER`)
- **And** ระบบแสดงส่วนหัวข้อ “สิทธิ์การใช้งาน”
- **And** ระบบแสดงส่วนหัวข้อ “เขตอันตราย (ลบบัญชี)”

#### Scenario 16.4: กำหนดสิทธิ์การใช้งานจริงตาม TARGET_ROLE (TC-ADM-USR-004)
- **Given** ผู้ดูแลระบบอยู่ที่หน้ารายละเอียดของผู้ใช้เป้าหมาย
- **When** ผู้ดูแลระบบเปลี่ยนระดับสมาชิกในช่องเลือกระดับสมาชิกเป็น `TARGET_ROLE` (`user-pro` หรือ `user-free`) แล้วกดปุ่ม “บันทึก”
- **Then** ระบบแสดงข้อความแจ้งเตือน “อัปเดตข้อมูลผู้ใช้สำเร็จ”
- **And** เมื่อทำการโหลดหน้าใหม่ (Reload) และย้อนกลับไปหน้ารายการผู้ใช้งาน ระดับสมาชิกของผู้ใช้เปลี่ยนเป็น `TARGET_ROLE` ตรงตามที่บันทึกไว้จริง

#### Scenario 16.5: ระงับบัญชีผู้ใช้งานด้วยข้อมูลจริง (TC-ADM-USR-005)
- **Given** ผู้ดูแลระบบอยู่ที่หน้ารายละเอียดของผู้ใช้เป้าหมายที่มีสถานะปกติ
- **When** ผู้ดูแลระบบทำเครื่องหมายในช่อง “ระงับบัญชีผู้ใช้” แล้วกดปุ่ม “บันทึก”
- **Then** ระบบแสดงข้อความแจ้งเตือน “อัปเดตข้อมูลผู้ใช้สำเร็จ”
- **And** เมื่อย้อนกลับไปหน้ารายการผู้ใช้งาน (`/admin/users`) ตารางแสดงสถานะผู้ใช้เป็น “ถูกระงับ (Banned)”

#### Scenario 16.6: ยกเลิกระงับบัญชีผู้ใช้งานด้วยข้อมูลจริง (TC-ADM-USR-006)
- **Given** ผู้ดูแลระบบอยู่ที่หน้ารายละเอียดของผู้ใช้เป้าหมายที่มีสถานะถูกระงับบัญชี
- **When** ผู้ดูแลระบบยกเลิกเครื่องหมายในช่อง “ระงับบัญชีผู้ใช้” แล้วกดปุ่ม “บันทึก”
- **Then** ระบบแสดงข้อความแจ้งเตือน “อัปเดตข้อมูลผู้ใช้สำเร็จ”
- **And** เมื่อย้อนกลับไปหน้ารายการผู้ใช้งาน (`/admin/users`) ตารางแสดงสถานะผู้ใช้กลับเป็น “ปกติ”

#### Scenario 16.7: ตรวจสอบหน้าต่างยืนยันการลบบัญชีและกดยกเลิก (TC-ADM-USR-007)
- **Given** ผู้ดูแลระบบอยู่ที่หน้ารายละเอียดของผู้ใช้เป้าหมาย
- **When** ผู้ดูแลระบบกดปุ่ม “ลบผู้ใช้งานนี้ถาวร” ในส่วนเขตอันตราย
- **Then** ระบบแสดง Pop-up หน้าต่างยืนยัน (Confirmation Dialog) พร้อมข้อความเตือน “ไม่สามารถย้อนกลับได้”
- **When** ผู้ดูแลระบบกดปุ่ม “ยกเลิก” ในหน้าต่างยืนยัน
- **Then** หน้าต่างยืนยันซ่อนลง (Detached) และผู้ดูแลระบบยังคงอยู่ที่หน้ารายละเอียดของผู้ใช้เป้าหมายเดิม โดยไม่มีการลบข้อมูลจริง
